# 0.1.1 授权修复候选版

此版修复：发现设备后遗漏 DEVICE_MANAGER 授权流程；通知监听未连接时缺少重新绑定；无启动入口；SDK 异常缺少详情；手机标题与系统状态栏重叠。

签名必须与 0.1.0 一致，版本号提升至 0.1.1 / versionCode 2。云端会核验原证书指纹，不允许生成替代密钥。暂存公开仓库的签名交换文件仅包含 AES-GCM 密文，密钥由本次云端临时 RSA 公钥封装；私钥不进入仓库或产物。

## 真机测试（依次执行）

1. 手机覆盖安装 APK，手表安装同次构建的 RPK。不要先卸载手机旧版；如签名冲突，停止并反馈。
2. 在小米运动健康确认手表已连接；手机打开 HY_WristNav，顶部应显示 0.1.1。
3. 点击“启动 · 自动连接手表”。如先进入通知使用权设置，授权后返回；随后程序查询设备并检查、申请小米互联设备管理权限。两种授权分开显示。
4. 检查“识别设备”“小米互联授权”“通信”“手表应用”。程序尝试打开手表应用；若系统未打开，手动在手表启动 HY_WristNav，应至少看到 WAITING / 等待导航。
5. 发送 DEMO：手表显示 DEMO、左转和 90 m；手机最近发送与手表确认序号相同且不为 -1。再发 STOP，应清除箭头并显示导航已停止。
6. 单次 DEMO 后等待超过 30 秒，应显示过期并清除箭头。保持手表应用在前台进行此项测试。
7. 真实高德导航前，通知监听必须为“已连接”。实际开始导航并确认通知栏存在导航通知，再看最后回调、解析规则、LIVE 数据和手表确认。
8. 最后再测试锁屏、抬腕、断连恢复。真实导航可由步行测试或乘客操作，避免驾驶中操作。

## 阻塞时停止对应测试

- 授权申请失败：复制诊断信息，保留失败阶段和异常详情。反复点 DEMO 不会重复申请权限；确认条件后再点启动。
- 已授权但注册接收仍被拒绝：反馈这个完整状态，继续查运动健康接口兼容，不把授权状态当作通信成功。
- 没有手表回应：先确认手表应用能打开，确认同包名/同签名配套安装；SDK 发送成功不等于手表已渲染。
- 通知已授权但未连接：重新绑定仍失败时，在设置中关闭再开启一次；仍未连接则反馈。该问题不阻碍独立 DEMO 通信测试。
- 有通知回调但解析失败：反馈解析规则、失败原因和脱敏字段摘要。

“复制诊断信息”只写入手机剪贴板，不自动上传。通知正文默认遮蔽；SDK 返回的异常详情用于定位互联问题。

云端编译、单元测试和签名检查不能替代真机验收；S4 自动打开页面、HyperOS 通知行为仍需按以上步骤验证。
